# Event and synchronization protocol

Every committed event contains `id`, `branch_id`, `tick`, `sequence`, discriminated `type`, typed `payload`, optional `actor_id`/`rationale`, and `causal_refs`. IDs are `branch:sequence`; entity IDs remain stable across ticks and forks. Sequence increases for every event, even multiple interventions at the same tick. Version is the last committed event sequence.

Event variants cover spawn/removal, movement, construction/upgrade/removal, production/consumption, transactions, price changes, communication/relationships, and applied interventions. The v1 core set is: `transaction_completed`, `price_changed`, `resource_produced`, `resource_consumed`; `building_constructed`, `building_upgraded`, `building_removed`; `lot_leased`, `plot_opened`; `job_applied`, `job_application_resolved`, `employment_changed`; `citizen_spawned`, `citizen_removed`, `citizen_moved`, `agent_spoke`; `intervention_applied`, `action_rejected`. The daily growth step emits spawn/removal and `plot_opened` (see `simulation-design.md`). Loan, trade, invention, relationship, vote, and rent events are beyond v1 core and already implemented.

`WorldUpdate` always contains a complete `state` plus associated events and matching branch/tick/sequence. A normal frame contains the new event batch; initial HTTP/socket states contain up to 100 recent events. Complete snapshots allow safe convergence across sequence gaps; `GET /api/events?after=<sequence>&limit=` pages durable history in ascending order if needed.

Event durability is independent of realtime transport. The engine emits typed outcomes; the existing HistoryStore saves Events, world and checkpoint in one transaction before any broadcast. A broadcast failure after commit is logged and does not fail the saved operation. Database failures still abort normally.

`GET /api/events?after=0&limit=100` returns a JSON array from persisted storage on the active branch, ordered by ascending sequence, strictly greater than `after`. Use the last returned sequence for the next request, keep one cursor per branch, and stop when the array is empty. Limit is 1–500 (default 100); negative cursors are invalid. Events survive API restarts; session action-attempt lookups do not. The SQL row has `created_at`, but the existing typed Event response uses tick/sequence and does not expose that timestamp. No frontend or WebSocket connection is required to write or read this ledger.

The browser rejects stale/equal versions and different-branch frames. On every socket reconnection it reloads `/api/world`. Epoch checks invalidate HTTP requests that started before a seek/switch. Historical mode ignores incoming live frames. A branch switch atomically replaces the world and event window, clears selection, and remounts entity animations. It never replays every historical movement. Transport retries use capped exponential backoff.

Playback and active branch are shared server session state. The initiating browser explicitly replaces state after activation; another tab with an old branch rejects foreign frames and must reload or select the active branch. User writes still cannot cross branches because the server checks branch and version. Per-client subscriptions are a future extension.

`rationale` is the agent's stated reason, not proof. Causal references are only emitted for a price change directly caused by the corresponding applied intervention. Full saved state records all outcomes, including hunger changes and RNG; events alone are not claimed to be an exhaustive reducer log.
